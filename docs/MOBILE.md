# 手机版说明

这份文档只讲**手机端怎么玩、怎么摆、为什么这么摆**。技术口径（帧数据、系统对照）在
[`ARCHITECTURE.md`](./ARCHITECTURE.md)。

---

## 1. 一句话

横屏、单人对电脑、左手摇杆右手四键。**判定盒和节奏完全不因设备改变**——手机版只是换了一套输入和画布缩放。

---

## 2. 操作

```
                 ┌─────────────────────────────┐
                 │                             │
                 │        游戏画面 320×224      │
                 │                             │
   ╭───╮         │                             │         ╭───╮
   │ ○ │  摇杆   │                             │   四键  │ C │
   ╰───╯         └─────────────────────────────┘   ◀ B   ╰───╯  D ▶
                                                        ╭───╮
                                                        │ A │
                                                        ╰───╯
```

| 操作 | 说明 |
|---|---|
| **左摇杆** | 8 向：←→ 移动/防御，↑ 跳，↓ 蹲；组合出 8 个方向（←↓＝蹲防） |
| **A** | 轻拳（↘ 菱形下方） |
| **B** | 轻脚（← 左方） |
| **C** | 重拳（↑ 上方） |
| **D** | 重脚（→ 右方） |
| **A+B** | 回避（同时按，菱形上 A 与 B 相邻） |
| **C+D** | 吹飞攻击 |
| **ABC** | MAX 发动 |

必杀技按**方向 + 攻击**输入：例如 `236 + A`＝↓↘→ 后按 A。

**摇杆手感**：死区 30%（半径比例），单轴阈值 36%。手指在死区里抖动不会让角色乱走；
斜方向靠"两轴同时超过阈值"判定，不是角度切片——手抖两度不会从"防御"变成"蹲防"。

## 3. 布局：按屏幕短边取比例

所有控件尺寸 = `min(屏幕宽, 屏幕高) × 系数`，所以 6 寸手机和 13 寸平板上**占屏比例一致**。

| 控件 | 系数 | 844×390 上实际 |
|---|---|---|
| 摇杆半径 | 0.170 | 66 px |
| 攻击键半径 | 0.062 | 24 px |
| 菱形中心到键 | 0.115 | 45 px |
| 边距 | 0.045 | 18 px |
| 功能条高 | 0.052 | 20 px |

布局算法在 `src/ui/pad-layout.ts`（纯函数，有 18 条测试：不出界、不重叠、等比缩放、安全区避让、320×240 极端窄屏）。

## 4. 画面缩放：桌面整数倍、手机铺满

| 设备 | 策略 | 原因 |
|---|---|---|
| 桌面 | 整数倍（1×/2×/3×…） | 像素画必须整数倍才锐利 |
| 手机 | **小数倍铺满** | 390 高的横屏上整数倍只能取 1×，画布缩成 320×224 蹲在正中间，四周全是黑边 |

手机横屏时画面比例（4:3）和屏幕比例（16:9）不一致，两侧必然留出一条。这条**不放纯黑**，
而是用暗渐变当画框，**手台就摆在这两条里**——既不挡画面，也不浪费拇指活动区。

> 想改回整数倍：去掉 `src/main.ts` 里 `computeViewport(..., { fill: IS_TOUCH })` 的 `fill`。

## 5. 屏幕相关

- **全屏**：第一次触摸时自动 `requestFullscreen()`，并尝试 `screen.orientation.lock('landscape')`。
  浏览器不支持或拒绝时静默跳过（iOS Safari 目前不允许网页锁全屏，表现是不锁，不影响玩）。
- **安全区**：刘海/圆角用页面上的 `#safe-probe` 读 `env(safe-area-inset-*)`，画布居中留出安全区，
  手台也按安全区往里挤（`padLayout(w, h, insets)`）。
- **竖屏**：盖一层「请横屏游玩」提示。竖屏时画面只有拇指大，不提供竖屏玩法。

## 6. 触屏实现细节（都是踩过的）

1. **多点触控**：每个按钮各自 `setPointerCapture`，摇杆单独跟踪自己的 `pointerId`，
   所以「按住 ← 同时点 A」不会互相顶掉。
2. **按下即命中**：摇杆不要求先按在圆心，落在底盘内就以触点为起点。
3. **补一帧**：按下和抬起都落在两帧之间时，抬起会把键留一帧再清（`VirtualPad.release`），
   否则鼠标单击/快速点按会丢输入。代价是松手后最多多走 1 帧（16ms）。
4. **粘键防护**：`pointercancel` / `lostpointercapture` 都要松键，否则来电或切后台回来会一直往前走。
5. **触感**：按键时 `navigator.vibrate(8)`，不支持就跳过。
6. **菜单点选**：模式菜单、选项屏、暂停菜单都支持直接点行（命中带上下各半个行距，行间无缝）。

## 7. 调试开关

| 参数 | 作用 |
|---|---|
| `?touch=1` | 桌面浏览器强制走触屏路径（铺满 + 点选），用来验手机布局 |
| `?art=proc` | 强制程序化绘制，和贴图版左右对比 |
| `?px=1` | 像素粒度（0.5 最细 / 16 最粗） |

命令行：

```bash
npm run dev          # 开发
npm run check        # tsc + vitest（提交门禁）
npm run art:check    # 素材自检（图集/头像/舞台/身高一致性）
```

## 8. 已知限制

- **没有联机**。输入层已经是「采样 → 位掩码」的单一出口，后续接帧同步只需替换 `p1In` 的来源；
  世界是确定性的（`hash()` 逐帧可比），回放/对战都能复用。
- **iOS 全屏**：Safari 不允许 `requestFullscreen`，只能靠“添加到主屏”后全屏运行。
- **超宽屏**（21:9）：两侧留白更宽，画面显得小；可接受，因为手台正好占满。
- **按键不可自定义**：菱形四键位置固定，键位表（A/B/C/D 对应哪个拳脚）在设置里可换预设。
