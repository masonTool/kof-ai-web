- [x] [T173] 音频混音：BGM/SFX 两条总线 + DynamicsCompressor + 手机外放中频补偿（打击音补 800Hz~2kHz 层）+ 首次触摸解锁 AudioContext → `npm run check` 全绿
  - 做了什么：①新增 `src/audio/graph.ts`——**一个** AudioContext、两条总线（`sfx` / `bgm`）、汇到一个 `DynamicsCompressor`（阈值 -18dB / 比率 4 / 启动 4ms）再出 destination；②`WebAudioSink` 与 `WebAudioBgm` 都改成走全局图，删掉各自的 ctx/master（原来两个 AudioContext 各自接 destination，等于没有混音）；③`SfxSpec` 加 `presence`，打击类音效补一层 1.4kHz 带通噪声（手机外放补偿）；④`unlockAudio()` 在画布 pointerdown 与**手台首次按下**时调用（手台在画布外，画布事件收不到）
  - 为什么合成一个 AudioContext：手机浏览器对同时存在的 AudioContext 数量有限制，多开容易被系统挂起；而且两路各自接 destination 就是直接叠加削顶，密集连段会糊成一团——压缩器正是治这个
  - 为什么中频补偿单独一层而不是调 EQ：小喇叭物理上放不出 100Hz 以下，把 thump 调响只会更糊；人耳对 1~2kHz 最敏感，"打到东西"全靠这层窄带噪声，所以按音效类型单独给量（轻击 0.5 / 重击 0.75 / 反击 0.85 / KO 0.5），环境音（挥空）不给
  - 验证：新增 4 条测试（node 下三个 API 均静默降级不抛、两条总线默认音量分开、打击类音效 presence > 0、挥空为 0）；`npm run check` **798 条全绿**；浏览器加载 + 点击后控制台无音频报错（只剩 favicon 404）
