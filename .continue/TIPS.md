# 踩坑提示 · TIPS

> **备查文档，按大模块分节**——模块名与 `OVERVIEW.md` 一一对应，它就是两边的链接键。
>
> 它装的是**"下次怎么做"**，不是事故档案：每条都要能直接照着做（症状 → 根因 → 处置）。
>
> 怎么被找到：动某个模块之前，先看 `OVERVIEW.md` 那个模块的「坑 / 注意」拿到一行摘要，
> 需要细节再按**模块名** grep 本文件（**别整份读**，很贵，也没必要）。
>
> 谁写、什么时候写：AI，**踩坑当场**或收尾时自问一次"这轮有没有会重复踩的坑"。
> 有就写，没有就跳过——**不写占位**。
>
> **收录门槛（三条不满足就别写）**：
> 1. 调了很久才定位（不是一眼看出来的）；
> 2. 改了 A 却红了 B，或工具 / 平台的隐蔽默认值反直觉；
> 3. 不记下来下次一定重踩，且重踩代价明显（排错时间 / 数据风险）。
>
> **不算坑**：语法记错、漏读文档导致的误判、临时的环境差异、一条命令就能查明的现象。
> 这类写进来会稀释真正有价值的条目，让人误以为"坑很多"——**宁可少写**。
>
> 与 `README.md` 的分工：README 只记**框架机制本身**的坑（队列 / 钩子 / 标记），
> 这里记**项目与工具**的坑（语言 / 构建 / 依赖 / 平台行为）。

## 模拟内核

### 1/60 秒的浮点累加会少跑一帧

- 症状：`FixedStepper.advance(1000)` 期望补 6 帧，实际只跑 5 帧；单测 asserting 帧数时偶发差 1。
- 根因：`TICK_MS = 1000/60` 除不尽，累加器做减法 6 次后余量比 `TICK_MS` 小了一点点（浮点误差），`while (acc >= stepMs)` 提前退出。
- 处置：比较时留余量——`while (acc + 1e-9 >= stepMs)`，减法后把负数抹成 0；不要改用"取整毫秒"，那会把高刷屏的 rAF 抖动带进逻辑帧。
- 适用面：任何"真实时间 → 固定逻辑帧"的累加器（`core/loop.ts`，将来录像回放/网络同步也走同一条）。
- 批次：20261024-1614

## 角色状态机

### 状态入口方法会清掉结算刚设好的字段

- 症状：命中后攻击方有 6 帧命中停顿、受击方却是 0，紧接着 5 条测试连锁红（受击方提前恢复、连段被拆开、伤害补正对不上）。
- 根因：`hit.ts` 先给双方 `addHitstop()`，再调防御方 `enterHitstun()`；而 `enterHitstun()` 开头有一句 `this.hitstop = 0`，把刚设好的值抹掉了。
- 处置：**结算层写入的字段，状态入口方法一律不许清**。要清就由结算层在设置前清，或换一个明确的 `reset()` 入口。改状态机时先问："这个字段是谁写的？"
- 适用面：`Fighter.enterHitstun/enterBlockstun/enterKnockdown/enterDizzy`、`reset()`，以及将来任何"进入某状态时顺手清一堆字段"的代码。
- 批次：20261024-1614

## 指令输入

### 命中停顿期间按键被吞掉，连段里的取消永远接不上

- 症状：5C 打中后立刻摇 236+A，招式不切换；把输入提前/延后几帧又好了，像是"取消窗口随机失效"。
- 根因：命中后双方进入 6~12 帧命中停顿，`Fighter.step` 在停顿里直接 `return`，那几帧的"按下"边沿就这样丢了——而玩家几乎一定是在停顿里输入的（停顿就是给你看命中反馈的）。
- 处置：冻结期间照常把输入喂给指令解析器，解析出的招式存进 `pendingMove`（8 帧），解冻那一帧再执行；`cancelInto` 自己也要判 `hitstop === 0`，否则会在冻结里改状态。
- 适用面：`sim/fighter.ts` 的 `step()`、一切"结算写字段 + 状态机读字段"的时序；将来做网络回滚时同理。
- 批次：20261024-1659

## 训练模式与入口

### 鼠标单击的按下+抬起落在两帧之间，逐帧采样等于没点

- 症状：屏幕上的 A 键用鼠标点没反应，按住 100ms 才有；触屏长按正常，桌面上点一下就"丢输入"。
- 根因：输入源每逻辑帧采样一次"当前按住集合"，而一次 click 的 down→up 可能都在同一帧内完成，采样时看到的始终是"没按"。
- 处置：输入源区分"按下后还没被采样过的键"与"已采样过的键"，前者在抬起时**保留一帧**（`VirtualPad.sampleFrame()` 消费后清除）；键盘不用管（人手的 keydown/keyup 天然跨帧）。
- 适用面：`ui/virtual-pad.ts`、任何自定义指针/手柄输入源；单元测试要按"帧"驱动，不能用真实时间。
- 批次：20261024-1659

## 角色状态机

### 数据里写了、结算层没读：招式无敌帧形同虚设

- 症状：鬼焼、紧急回避看着有动作，但照样被打；`invuln` 字段写了几个月没人报错，因为没有任何断言覆盖"无敌窗口内打不中"。
- 根因：`MoveDef.invuln` 从数据层就定义好了，`hit.ts` 的 `collect()` 只判了倒地/起身无敌，没有消费招式自带的无敌窗口。
- 处置：结算前先过 `isInvulnerable(defender, hit)`（full / low / air 三种），再判判定盒相交；新加机制时**顺着数据字段 grep 一遍消费方**，能发现一串"定义了但没人读"的字段。
- 适用面：`sim/hit.ts`、`data/schema.ts` 的任何可选字段（invuln / travel / meterCost / cancel.window 都曾或仍可能没被读）。
- 批次：20261024-1720

## 界面流程与音效

### 长指令被短指令吃掉：63214 出成了 214

- 症状：八神贴身摇 63214+A 想要屑風（指令投），实际出来的是葵花；把距离拉远反而正常。
- 根因：招式选择按"类别"排序（必杀 > 投技），而 63214 的尾段本身就包含 214，两个指令同时成立时，短的那个类别更高就先出了。
- 处置：排序第一关键字改成**指令长度**（`motionLength()`，无指令的招按 1 算），长度相同再比类别。这样 63214 压过 214、236 压过 6（普通投），而 AB/CD 仍靠类别压过指令技。
- 适用面：`sim/controls.ts` 的候选排序；以后加任何"带方向前缀的投技/派生技"都会撞上。
- 批次：20261024-1726

### playwright-cli 的 run-code 不是浏览器环境

- 症状：自测脚本里用 `setTimeout` 报 `ReferenceError: setTimeout is not defined`；直接写 `async (page) => {...};` 报 `Unexpected token ';'`。
- 根因：`run-code` 把参数当"函数源码"在 Node 侧求值，只有 `page` 可用，没有 DOM 的定时器；结尾多一个分号会让它拼出来的调用表达式语法错。
- 处置：等待一律用 `page.waitForTimeout(ms)`；脚本文件结尾不要分号；页面内的定时/动画用 `page.evaluate(async () => { ... requestAnimationFrame ... })`。
- 适用面：`scripts/*.mjs` 这类自测脚本。
- 批次：20261024-1726

## 模拟内核

### 在 step 里生成实体，它当帧就被推进了一次

- 症状：飞行道具刚生成就往前多飞了一帧，贴脸放技能时看起来"出生即命中"；换个写法又变成少飞一帧。
- 根因：`World.step` 用 `for (let i = 0; i < this.entities.length; i++)` 遍历，角色在 step 里 `add()` 了新实体后数组变长，循环顺带把它也推进了一次。
- 处置：遍历前先快照长度（`const count = this.entities.length`）；删除实体统一走 `world.sweep()`（把 dead 标记的在帧末回收），不要在遍历里 splice。
- 适用面：`sim/world.ts`；以后加召唤物、碎片、多段道具同理。
- 批次：20261024-1749

### 换角色不要重建 Fighter 实例

- 症状：3v3 换人时如果 new 一个 Fighter 塞回世界，实体 id 会变，输入映射（按实体下标分发）和哈希都会乱。
- 根因：`World.step` 用实体**下标**对齐输入，`id` 又参与哈希；中途 add 一个新人会打乱两处。
- 处置：换人只改 `Fighter.char` / `maxHp` 再 `reset()`（`switchChar()` 已封装），实体本身不动。
- 适用面：`game/match.ts` 的换人、以后的状态继承/变身。
- 批次：20261024-1749

## CPU

### AI 的攻击距离写大了，它会站在原地永远挥空

- 症状：CPU 明明"在进攻"，玩家却一点血都不掉；看状态栏它在不停出招。把距离打印出来才发现一直停在 60 多像素处出拳。
- 根因：AI 的靠近条件是 `dist > ATTACK_RANGE + 20`，也就是走到 66px 就停；而通常技最远只够到 46px（判定盒 x+宽），于是每一拳都差 20px。
- 处置：靠近阈值要用"招式真正够到的距离"（本项目 `ATTACK_RANGE - 4`），并且**测试要断言玩家掉血**而不是只断言"CPU 出过招"——后者会让这种 bug 一路绿灯。
- 适用面：`ai/cpu.ts` 的所有距离判断；换角色/换招式表时阈值要跟着复核。
- 批次：20261024-1826

## 判定与结算

### 气槽没有上限：HUD 看着满的，实际还在往上涨

- 症状：BOSS 自动回气那条测试报"期望 100、实际 102.999"；普通角色长时间互殴后，`meter` 也会涨到几百。
- 根因：`addMeter()` 只夹了下界（`Math.max(0, ...)`），没夹上界；HUD 的 `meterRatio()` 做了截断，**显示层盖住了数据层的错**，所以一直没人发现。
- 处置：`addMeter()` 里 `Math.min(METER_MAX, ...)`；"资源类字段"统一在写入处夹，不要在读取处夹——读取处夹会让两处口径不一致。
- 适用面：`sim/fighter.ts` 的 meter/hp/stunGauge/guardGauge；将来加"气槽上限随角色变化"时同样只在写入处处理。
- 批次：20261024-2215

## 界面流程与音效

### 读盘不消毒＝用户改一下就崩

- 症状（预判后主动防的）：设置存进 localStorage 后，用户手改成 `{"roundsToWin":"两局"}` 或删一半，下次打开就白屏。

## 界面流程与音效

### 音序器的 pattern 下标必须由"步边界"反推，不能用游标算

- 症状：分段推进和一次推进得到的音符数差一个（11 vs 10），而且听起来像"某几拍突然少了个声部"。
- 根因：`index = floor(cursor / step)` —— 游标停在第 3.3 步时，下一个要奏的是第 4 步，但用游标算出来是 3，整条旋律从此错位一步；bass 轨有空拍，错位后音符数就对不上了。
- 处置：先算出下一个步边界 `boundary = ceil(cursor/step)*step`，再 `index = round(boundary/step)`；用 `round` 而不是 `floor`，避免浮点在整步上算成 3.9999。
- 适用面：`audio/bgm.ts` 的 `BgmPlayer`；任何"按时间切片取离散事件"的调度器（节拍器、动画关键帧、网络同步的输入采样）。
- 批次：20261024-2330

### 设置持久化之后，自测脚本之间会互相污染

- 症状：`selftest-audio-pause.mjs` 单独跑全绿，跟在别的脚本后面跑就"方向键下移光标"失效。
- 根因：上一个脚本把 `keyPreset` 改成 WASD 并存进了 localStorage，下一个脚本按 ArrowDown 自然没反应——**这是功能正确，不是 bug**。
- 处置：会改持久化状态的脚本，开头先把要用的设置归零（`settings.keyPreset = 0; save()`），别假设"页面一开是默认值"。
- 适用面：`scripts/selftest-*.mjs`；以后加"存档/回放"这类落盘功能时同理。
- 批次：20261024-2330

## 对局流程

### 录"键盘输入"≠录"喂进模拟层的输入"

- 症状：回放重演后对局哈希差一点点（计时器差 5 帧、世界哈希完全对不上），单测却全绿。
- 根因：单测里双方输入都是自己喂的；真实浏览器里 P2 是 **CPU**，输入由 `CpuBrain` 生成。我录的是键盘原始输入（P2 恒为 0），重演时没有 CPU，状态自然分叉。
- 处置：录制点放在 `TrainingSession.step()` 之后，录 `lastInputs`（**真正传给 `Match.step` 的那一对**），假人/CPU/触屏的输入全都包含在内。
- 适用面：`ui/training.ts` 的 `lastInputs`、`game/replay.ts`；以后做网络同步（同样要传"实际生效的输入"）同理。
- 批次：20261025-0010

### 回放"看结局"不能继续推进世界

- 症状：回放跑完后画面继续动，哈希持续变化，导致"重演结果"和"原局结果"对不上。
- 处置：回放模式下播完就把这一帧直接 `return`（画面冻结），不要再走无输入的一帧；`replayDone` 也据此判断。
- 适用面：`main.ts` 的回放分支；任何"播完要停住"的重播/观战功能。
- 批次：20261025-0010

## 角色绘制与特效

### 表现层的数据不要塞进玩法数据

- 症状（提前避开的）：想给角色加"发型/身高"，第一反应是往 `CharDef` 里加 `look` 字段——但那样每次调外观都要碰招式文件，`validateChar` 也会多一堆跟玩法无关的校验。

- 适用面：`render/looks.ts`、`render/poses.ts`；以后加"皮肤/胜利动作/登场台词"同理。
- 批次：20261025-0105

## 界面流程与音效

### 一个按键被两处消费：返回键把两层菜单一起退了

- 症状：在"按键设置"屏按 B 返回，结果直接退到了模式选择（跳过了选项屏）。

- 适用面：`main.ts` 的按键屏分支；以后做"输入框/重命名/录像导入"这类要接管键盘的界面同理。
- 批次：20261025-0135

## 角色状态机

### "刚起手"不能用 `moveFrame === 0` 判断

- 症状：超必杀闪光在真实对局里正常，单测里怎么都不触发。
- 根因：`moveFrame === 0` 只在"这一帧的 `step` 内部起手"时成立；测试（以及训练模式、回放）都是**先 `startMove()` 再 `step()`**，推进一帧后 `moveFrame` 已经是 1。

- 决定：`Match.superFlash` 同时驱动"双方定格"和"闪白"，并进 `hash()`。

## 舞台与镜头

### 临时改镜头要改"目标"，不能直接改 `zoom`

- 症状（差点写下）：运镜时直接 `cam.zoom = 1.45`，结果下一帧就被拉回原样。
- 根因：镜头是**平滑逼近目标**的（每帧最多变 0.04），`update()` 每帧都会用 `computeTargets()` 重算目标并朝它逼近；直接改当前值只是改了"这一刻"。
- 处置：加 `Camera.zoomOverride`，在 `computeTargets()` 里替换掉"距离决定缩放"那一步；清空即恢复自动。
- 附带：覆盖期间左右夹取仍要走 `clampX(x, zoom)`，否则拉近后画面会露出舞台外。
- 适用面：`sim/camera.ts`；以后做"终结技特写""KO 拉近"同理。
- 批次：20261025-0450

### 边跑边采样：状态只活十几帧时，跑完再读就没了

- 症状：自测里"闪光期间镜头拉近"读到 `null`，但手动一步步看是对的。
- 根因：`requestAnimationFrame` 双跳一次 = 2 个逻辑帧，闪光只有 12 帧，10 次循环就跑完了；循环结束后读到的自然是"已结束"。
- 处置：在循环**内部**把每次采样 push 进数组，最后挑"闪光 > 0"的那一条断言。
- 适用面：`scripts/selftest-*.mjs`；任何短于 20 帧的演出（闪白/命中停顿/受身窗口）都适用。
- 批次：20261025-0450
